# Record in Bar for Mac 需求说明书

## 1. 文档信息

- 项目名称：Record in Bar for Mac
- 文档类型：需求说明书
- 当前版本：v0.1
- 更新时间：2026-04-25

## 2. 项目背景

用户在观看视频、阅读小说、浏览文章或思考某个主题时，常常会产生零散的想法、疑问和灵感。这些内容需要尽快记录，但传统笔记软件通常启动重、层级深、操作慢，不适合高频即时记录。

本项目拟开发为一个 macOS 状态栏应用。用户可在状态栏中快速打开应用，对多个对象分别记录标题与笔记内容，并在需要时手动调用 AI 对当前对象下的记录进行总结归纳。

## 3. 产品目标

### 3.1 核心目标

- 提供极低打断的即时记录体验
- 支持多个对象并行维护与快速切换
- 将零散记录实时保存到本地数据库
- 允许用户手动调用 DeepSeek 对当前对象内容进行总结

### 3.2 非目标

- 不做复杂的长文写作编辑器
- 不做多人协作
- 不做云同步
- 不做自动触发 AI 分析
- 不做通用知识库管理系统

## 4. 目标用户

- 看视频时需要快速记录观点的人
- 阅读小说、文章、播客时需要记录感受与线索的人
- 经常产生碎片化思路，希望稍后用 AI 做整理的人

## 5. 产品定位

一个运行于 macOS 状态栏中的多对象即时记录工具。

每个对象可理解为一个独立的“文件”或“主题卡片”。用户可同时维护多个对象，在它们之间快速切换，并对每个对象分别记录笔记与生成 AI 总结。

## 6. 核心概念

### 6.1 对象（Topic）

对象表示当前正在记录的主题，可以是：

- 一个视频
- 一篇小说
- 一篇文章
- 一个播客
- 一个思考主题

### 6.2 记录项（Note Item）

记录项表示用户在某个对象下输入的一条即时内容，通常为：

- 感受
- 观点
- 问题
- 联想
- 灵感

### 6.3 AI 总结（AI Summary）

AI 总结是用户手动触发后，由 DeepSeek 基于当前对象下全部记录生成的结构化总结结果。

## 7. 使用场景

### 7.1 视频场景

用户正在看一个视频，想到一个观点，点击状态栏图标，选择该视频对应对象，输入一句笔记并关闭弹窗。

### 7.2 小说场景

用户在阅读小说时记录人物关系、关键线索或某段文字带来的感受，后续统一触发 AI 总结。

### 7.3 思考场景

用户围绕某个想法持续记录多个片段，在积累若干条后手动触发 AI 归纳主要方向、问题和可延伸思路。

## 8. 功能范围

### 8.1 状态栏常驻

- 应用常驻于 macOS 状态栏
- 点击状态栏图标可展开主面板
- 主面板关闭后应用不退出

### 8.2 多对象管理

- 支持创建多个对象
- 支持查看对象列表
- 支持切换当前对象
- 支持重命名对象
- 支持删除对象
- 支持按最近更新时间排序

### 8.3 当前对象编辑

- 支持编辑当前对象标题
- 支持输入记录项内容
- 支持新增记录项
- 支持查看当前对象下的记录列表
- 支持按时间顺序展示记录项

### 8.4 自动本地保存

- 标题变更后自动保存
- 记录项创建后自动保存
- 删除或重命名对象后自动保存
- 应用重启后可恢复所有本地数据

### 8.5 AI 总结

- 用户手动点击按钮触发 AI 分析
- AI 仅对当前对象下的记录进行处理
- 支持展示最近一次 AI 总结结果
- 生成失败时展示错误信息

### 8.6 设置页

- 支持录入 DeepSeek API Key
- 支持选择模型
- 支持配置 Thinking 开关
- 设置应持久化保存到本地

## 9. AI 相关需求

### 9.1 AI 服务

- 使用 DeepSeek API

### 9.2 模型配置

设置页提供以下模型选择：

- `deepseek-v4-flash`
- `deepseek-v4-pro`

并提供：

- `Thinking` 开关

### 9.3 触发方式

- AI 由用户手动触发
- 不在用户新增记录时自动调用

### 9.4 输出结构

AI 总结建议输出以下结构：

- 一句话总结
- 关键观点
- 疑问点
- 可延伸思路

## 10. 界面与交互要求

### 10.1 主体原则

- 打开即用
- 操作路径短
- 记录优先
- 切换对象要足够快

### 10.2 状态栏主面板建议布局

- 顶部：对象切换区 / 对象列表入口
- 中部：当前对象标题输入区
- 中下：记录输入框与新增操作
- 下部：记录列表
- 底部或侧栏：AI 总结操作与展示区域

### 10.3 交互反馈

- 所有操作按钮与图标在鼠标悬停时必须有阴影效果
- Hover 状态建议同时叠加轻微背景变化
- Pressed 状态建议有轻微下压感
- 禁用态需要可区分

### 10.4 体验要求

- 新建对象操作应在少量步骤内完成
- 切换对象时不应丢失当前已保存数据
- 输入记录时不要求用户手动点击保存

## 11. 本地数据存储要求

- 所有业务数据保存在本地数据库
- 设置数据保存在本地
- 数据需具备稳定持久化能力
- 应用异常退出后已保存数据不能丢失

## 12. 主要页面

### 12.1 状态栏主面板

用途：

- 快速切换对象
- 快速输入记录
- 查看当前对象已有内容
- 触发 AI 总结

### 12.2 设置页面

用途：

- 配置 DeepSeek API Key
- 配置模型与 Thinking 选项

### 12.3 历史 / 对象列表视图

用途：

- 查看全部对象
- 切换、重命名、删除对象

## 13. 用户流程

### 13.1 新建对象并记录

1. 用户点击状态栏图标
2. 新建一个对象
3. 输入对象标题
4. 在记录输入框中写入一条内容
5. 系统自动保存到本地数据库

### 13.2 切换对象继续记录

1. 用户打开状态栏主面板
2. 从对象列表选择另一个对象
3. 查看该对象已有记录
4. 输入新记录
5. 系统自动保存

### 13.3 触发 AI 总结

1. 用户进入某个对象
2. 点击 `AI 总结`
3. 系统读取当前对象标题与记录项
4. 调用 DeepSeek API
5. 返回结构化总结内容并展示
6. 结果保存到本地

## 14. 非功能需求

### 14.1 性能

- 状态栏面板打开应足够迅速
- 新增记录后应立即完成本地落库
- 对象切换时界面反馈应流畅

### 14.2 可用性

- 输入区域应始终保持清晰易达
- 错误提示应明确，例如 API Key 缺失、网络失败、模型调用失败

### 14.3 可维护性

- AI 调用逻辑、数据层、UI 层应分离
- 模型配置应可扩展，避免写死到界面逻辑中

## 15. MVP 范围

首版只实现以下内容：

- 状态栏常驻
- 多对象创建、切换、重命名、删除
- 对象标题维护
- 记录项新增与展示
- 自动保存到本地数据库
- 设置页配置 DeepSeek API Key、模型、Thinking
- 手动触发 AI 总结
- AI 结果本地保存与展示
- 按钮与图标 Hover 阴影反馈

## 16. 后续扩展方向

- 对记录项增加分类，如观点、疑问、灵感
- 支持搜索对象与记录项
- 支持 Markdown 导出
- 支持历史 AI 总结版本
- 支持不同对象类型对应不同提示词模板
