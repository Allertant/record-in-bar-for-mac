# Record in Bar for Mac 架构设计说明书

## 1. 文档信息

- 项目名称：Record in Bar for Mac
- 文档类型：架构设计说明书
- 当前版本：v0.1
- 更新时间：2026-04-25

## 2. 设计目标

本项目需要满足以下技术目标：

- 作为 macOS 状态栏应用稳定运行
- 支持多对象即时记录与快速切换
- 所有业务数据持久化到本地数据库
- 提供清晰可维护的 UI、领域、数据、AI 集成分层
- 支持通过设置页面配置 DeepSeek API Key、模型和 Thinking 开关

## 3. 技术选型建议

### 3.1 客户端框架

- 平台：macOS
- UI：SwiftUI
- 生命周期：SwiftUI App

选择理由：

- SwiftUI 适合快速搭建 macOS 菜单栏应用
- 与系统状态栏、设置页、窗口管理集成自然
- 便于以声明式方式维护多视图状态

### 3.2 本地持久化

- 首选：SwiftData
- 备选：Core Data + SQLite

建议首版优先采用 SwiftData，原因如下：

- 与 SwiftUI 集成成本低
- 可直接映射模型对象
- 足以覆盖首版本地持久化需求

若后期需要更复杂迁移策略或更细粒度控制，可再评估切换或下沉到 Core Data。

### 3.3 AI API 集成

- 服务：DeepSeek API
- 协议风格：OpenAI-compatible Chat Completions
- 基础地址：`https://api.deepseek.com`

当前建议支持的模型配置：

- `deepseek-v4-flash`
- `deepseek-v4-pro`

AI 调用由客户端主动发起，仅在用户手动触发总结时执行。

## 4. 总体架构

建议采用分层架构：

- 表现层（Presentation）
- 领域层（Domain / Application）
- 数据层（Data）
- 基础设施层（Infrastructure）

## 5. 模块划分

### 5.1 Presentation 层

负责：

- 状态栏图标与菜单入口
- 主面板视图
- 对象切换与列表展示
- 记录输入与记录列表展示
- AI 总结结果展示
- 设置页面
- Hover / Pressed 等交互状态

建议子模块：

- `MenuBar`
- `TopicList`
- `TopicEditor`
- `NoteComposer`
- `SummaryPanel`
- `Settings`

### 5.2 Domain / Application 层

负责：

- 对象管理用例
- 记录项管理用例
- AI 总结用例
- 设置读取与更新
- 业务校验

建议服务：

- `TopicService`
- `NoteService`
- `SummaryService`
- `SettingsService`

### 5.3 Data 层

负责：

- 本地数据库读写
- 数据模型持久化
- Repository 抽象与实现

建议仓储：

- `TopicRepository`
- `NoteRepository`
- `SummaryRepository`
- `SettingsRepository`

### 5.4 Infrastructure 层

负责：

- DeepSeek API 客户端
- Key 管理
- 日期、日志、错误映射等基础能力

建议组件：

- `DeepSeekClient`
- `PromptBuilder`
- `APIErrorMapper`

## 6. 核心数据模型

### 6.1 Topic

用于表示一个独立记录对象。

建议字段：

- `id: UUID`
- `title: String`
- `type: String`
- `sortOrder: Int?`
- `createdAt: Date`
- `updatedAt: Date`

说明：

- `type` 首版可保留为字符串，支持 `video`、`novel`、`article`、`other`
- 排序可优先使用 `updatedAt`，`sortOrder` 预留给未来手动排序

### 6.2 NoteItem

用于表示对象下的一条记录。

建议字段：

- `id: UUID`
- `topicId: UUID`
- `content: String`
- `createdAt: Date`
- `updatedAt: Date`

### 6.3 AISummary

用于保存某对象最近一次或多次 AI 总结结果。

建议字段：

- `id: UUID`
- `topicId: UUID`
- `model: String`
- `thinkingEnabled: Bool`
- `summary: String`
- `keyPoints: [String]` 或序列化文本
- `questions: [String]` 或序列化文本
- `nextIdeas: [String]` 或序列化文本
- `createdAt: Date`

首版若为简化持久化，可统一保存为结构化文本；后续再演进为可查询字段。

### 6.4 AppSettings

用于保存应用设置。

建议字段：

- `id: UUID`
- `deepSeekApiKey: String`
- `selectedModel: String`
- `thinkingEnabled: Bool`
- `updatedAt: Date`

说明：

- 若对安全性要求更高，API Key 后续可迁移至 Keychain，仅在数据库中保存引用状态

## 7. 状态管理设计

建议使用 `Observable` / `ObservableObject` 驱动界面状态。

可拆分为：

- `AppViewModel`
- `TopicListViewModel`
- `CurrentTopicViewModel`
- `SettingsViewModel`

职责建议：

- `AppViewModel`：管理当前选中对象、全局刷新与窗口状态
- `TopicListViewModel`：加载对象列表，处理新建、删除、重命名
- `CurrentTopicViewModel`：处理当前对象标题、记录列表、新增记录、AI 总结
- `SettingsViewModel`：处理模型配置、API Key 配置与合法性检查

## 8. 关键业务流程

### 8.1 应用启动

1. 初始化 SwiftUI App
2. 初始化本地持久化容器
3. 加载设置
4. 加载对象列表
5. 恢复最近使用对象或默认选中第一个对象
6. 渲染状态栏入口与主面板

### 8.2 新建对象

1. 用户点击新建对象
2. 创建 `Topic`
3. 持久化到本地数据库
4. 刷新对象列表
5. 自动切换到新对象

### 8.3 新增记录

1. 用户在当前对象下输入文本
2. 提交后创建 `NoteItem`
3. 更新 `Topic.updatedAt`
4. 立即写入本地数据库
5. 刷新当前对象记录列表与对象排序

### 8.4 手动 AI 总结

1. 用户点击 `AI 总结`
2. 校验 API Key、模型配置、当前对象内容是否存在
3. 读取当前对象标题与全部记录项
4. 构造提示词
5. 调用 DeepSeek Chat Completions API
6. 解析返回内容
7. 持久化 `AISummary`
8. 刷新界面展示

## 9. AI 集成设计

### 9.1 配置来源

AI 请求参数来自设置页：

- API Key
- selectedModel
- thinkingEnabled

### 9.2 请求结构

请求使用 Chat Completions 风格。

必要字段：

- `model`
- `messages`

可选字段：

- `thinking`
- `reasoning_effort`

建议：

- `thinkingEnabled = true` 时，请求体附带 `thinking: { "type": "enabled" }`
- `reasoning_effort` 首版可固定为中等或高，后续再开放设置

### 9.3 提示词策略

系统提示词建议约束输出结构，确保结果稳定：

- 一句话总结
- 关键观点
- 疑问点
- 可延伸思路

用户输入内容由以下信息拼接：

- 当前对象标题
- 当前对象类型
- 当前对象下全部记录项

### 9.4 错误处理

需要覆盖以下情况：

- API Key 缺失
- 网络请求失败
- DeepSeek 返回错误码
- 响应格式不符合预期
- 当前对象没有记录内容

界面需给出明确可理解的错误文案。

## 10. 本地存储设计

### 10.1 持久化策略

- 创建对象即落库
- 创建记录即落库
- 修改标题即落库
- AI 总结完成后即落库
- 设置变更即落库

### 10.2 数据一致性

以下操作应在单一事务或顺序可控流程内完成：

- 新增记录并更新对象时间戳
- 删除对象及其关联记录、总结

### 10.3 删除策略

删除 Topic 时，级联删除：

- 关联 NoteItem
- 关联 AISummary

## 11. UI 架构建议

### 11.1 主面板区域划分

- 顶部工具栏：新建、设置、关闭、对象切换
- 左侧对象区：对象列表
- 右侧编辑区：标题、记录输入、记录列表、AI 总结

如果首版希望更轻量，也可采用单列布局：

- 顶部切换对象
- 中部编辑与记录
- 底部总结

### 11.2 交互样式约束

针对按钮和图标，需要统一交互组件：

- 默认态：轻量背景或透明背景
- Hover：增加阴影与背景高亮
- Pressed：阴影减弱并轻微缩放或下沉
- Disabled：降低透明度并取消 Hover 强反馈

建议抽象：

- `HoverableIconButtonStyle`
- `HoverablePrimaryButtonStyle`

以保证全局视觉一致性。

## 12. 安全与隐私

- 所有业务数据默认仅保存在本地
- 不做云同步
- DeepSeek API Key 为敏感数据，建议后续迁移至 Keychain
- 向 AI 发送的数据仅限用户主动触发总结时的当前对象内容

## 13. 可扩展性设计

为后续功能预留以下扩展点：

- 不同对象类型的不同提示词模板
- 多次 AI 总结版本历史
- 搜索能力
- Markdown 导出
- 多窗口模式
- 本地全文检索

## 15. 开发优先级建议

### 第一阶段

- 状态栏应用基础壳
- Topic / NoteItem / AppSettings 建模
- 本地数据库接入
- 多对象增删改查
- 当前对象记录输入与展示

### 第二阶段

- 设置页
- DeepSeek API 接入
- 手动 AI 总结
- 错误处理与加载状态

### 第三阶段

- UI 打磨
- Hover 阴影统一组件
- 数据恢复细节
- 删除确认与可用性优化
