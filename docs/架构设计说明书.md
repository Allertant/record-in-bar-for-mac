# Record in Bar for Mac 架构设计说明书

## 1. 文档信息

- 项目名称：Record in Bar for Mac
- 文档类型：架构设计说明书
- 当前版本：v0.2
- 更新时间：2026-05-06

## 2. 当前实现目标

当前版本围绕以下目标组织代码：

- 作为 macOS 状态栏应用稳定运行
- 支持多对象记录、搜索、切换与历史恢复
- 记录标题、正文、图片、AI 总结全部持久化到本地
- 保持编辑页在状态栏弹层中可用
- 将复杂页面职责按功能拆分，降低单文件复杂度

## 3. 技术选型

### 3.1 客户端框架

- 平台：macOS
- UI：SwiftUI
- 生命周期与状态栏：AppKit `NSStatusItem` + `NSPopover` + SwiftUI 宿主视图

说明：

- 状态栏入口与弹层控制由 `AppDelegate` 管理
- 主要页面仍然使用 SwiftUI
- 需要更细粒度控制的位置下沉到 AppKit，例如滚动偏移恢复、富文本图片交互、预览窗口管理

### 3.2 本地持久化

- SwiftData
- SQLite store

当前实现包含：

- 自动重建不兼容旧 store 的容错逻辑
- 设置单例初始化
- 图片文件与数据库记录分离保存

### 3.3 AI 集成

- 服务：DeepSeek API
- 客户端：自定义 `DeepSeekClient`
- 提示词构造：`PromptBuilder`
- 后台任务协调：`AISummaryCoordinator`

AI 总结为用户手动触发，不自动执行。

## 6. 当前关键数据流

### 6.1 编辑保存

1. 编辑页加载 `Topic` 与最新 `NoteItem`
2. 文本变更写入 `draftTitle` / `draftNote`
3. 通过防抖调度 `persistDraft`
4. 若内容为空则清理相关 `NoteItem`、`NoteImage`、`AISummary` 与 `Topic`
5. 若内容存在则更新或创建记录

### 6.2 正文图片

1. 用户粘贴图片
2. 图片压缩为 JPEG
3. 文件写入图片目录
4. 创建 `NoteImage`
5. 正文中插入 `[IMG:uuid]` marker
6. `RichTextEditor` 根据 marker 渲染 attachment

### 6.3 AI 总结

1. 用户点击 `AI 分析`
2. 更新 `Topic.aiSummaryStatus`
3. `AISummaryCoordinator` 入队
4. `DeepSeekClient` 请求模型
5. 结果写入 `AISummary`
6. 编辑页展示最新总结

### 6.4 正文图片预览

1. 用户 hover 到正文图片右上角按钮
2. 点击后进入独立预览窗口
3. 预览顺序按正文中 `[IMG:uuid]` 的出现顺序决定
4. 可在预览窗口中切换上一张/下一张

### 6.5 分享图片

1. 用户打开分享弹层
2. 选择分享图片
3. 基于标题、正文、图片 marker 与 AI 总结生成 `ShareableNoteCard`
4. 通过 `ImageRenderer` 转为 `NSImage`
5. 先复制到剪贴板
6. 再显示页内图片预览

## 7. 当前交互架构约束

当前实现有几个明确约束：

- 状态栏主面板使用 `NSPopover`
- 图片预览使用独立 `NSPanel`
- 分享图片预览仍在编辑页页内展示
- 主页滚动恢复使用真实 `NSScrollView` 偏移，而不是 `scrollTo(item)`

这些约束来自已验证过的稳定性选择，而不是单纯的代码风格偏好。

## 9. 当前维护建议

后续继续调整编辑页时，建议遵守：

1. 优先新增 `EditorPageView+*.swift` 扩展文件，不再把逻辑回填到主文件。
2. 拆分阶段只搬运代码，不改交互和样式。
3. 涉及图片、滚动、popover 的改动后必须重新验证：
   - `swift build`
   - `swift test`
   - 手动冒烟检查
